About This Project

Background, datasets, preprocessing pipeline, evaluation methodology, and attributions.

Project Overview

This project is a full-stack NLP analytics application built as part of a Data Analytics internship portfolio (OIBSIP). It demonstrates end-to-end data analytics: raw corpus ingestion, tokenization, statistical language model construction, algorithmic spelling correction, evaluation, and interactive visualization — all served via a Flask web application deployed to Vercel.

The core NLP models are implemented from scratch in Python: a Bigram language model, a Trigram language model, an edit-distance spell corrector, and a probabilistic spell corrector based on Peter Norvig's classic approach. No pre-trained neural models are used.

Datasets

big.txt — Peter Norvig's Text Corpus ↗ norvig.com/big.txt

A ~6.5 MB concatenated plain-text file compiled by Peter Norvig from public-domain books and other English text. Used as the training corpus for all language models. After tokenization it yields approximately 1.1 million tokens and a vocabulary of roughly 29,000 unique words.

Format: plain text · Size: ~6.5 MB · License: public domain

spell-errors.txt — Norvig Spell Error Dataset ↗ norvig.com/ngrams/spell-errors.txt

A ~451 KB structured file listing correct English words and their commonly observed misspellings, compiled by Peter Norvig. Each line contains a correct word followed by a colon and comma-separated misspellings. Used to construct test pairs for evaluating spell correctors and to validate that the correctors handle real-world error patterns. The parsed dataset yields over 39,000 misspelling/correction pairs.

Format: structured text · Size: ~451 KB · License: public domain

Preprocessing Pipeline

  1. Tokenize — Lowercase the corpus and extract word tokens using a regex ([a-z]+), discarding numbers, punctuation, and HTML artifacts.
  2. Build vocabulary — Count unigram frequencies. Words appearing fewer than a minimum threshold may be excluded depending on configuration.
  3. Build bigrams — Slide a window of size 2 over the token list and count all (w₁, w₂) pairs. Compute MLE probabilities per context word.
  4. Build trigrams — Slide a window of size 3 and count all (w₁, w₂, w₃) triples. Compute MLE probabilities per 2-word context.
  5. Serialize — Dump the vocabulary, bigrams, and trigrams to data/processed/model_data.json (~18.5 MB). This avoids re-processing the corpus on every server startup. The correctors are reconstructed directly from the vocabulary dict at load time.

Evaluation Methodology

Autocomplete

A held-out set of trigram contexts was created from the corpus. The last word of each context was treated as the ground-truth target. The model was asked to predict the top-k candidates given the preceding words. Metrics:

  • Top-1 Accuracy — Fraction of test cases where the ground-truth word was the model's first prediction.
  • Top-3 Accuracy — Fraction of test cases where the ground-truth word appeared anywhere in the top-3 predictions.
  • Mean Reciprocal Rank (MRR) — Average of 1 / rank(correct word), where rank is 0 for misses. Rewards models that rank the correct word higher.

Autocorrect

50 misspelled/correct pairs were sampled from spell-errors.txt. Each corrector was given the misspelled word and asked to return its top candidates. Metrics:

  • Top-1 Accuracy — Fraction of pairs where the corrector's top candidate matched the intended correct word.
  • Top-3 Accuracy — Fraction of pairs where the correct word appeared in the top-3 suggestions.

All reported metrics are previously reported baseline results. They were produced by the evaluation scripts in src/evaluation.py and recorded in the project notebook; they are not independently re-verified at deployment time.
